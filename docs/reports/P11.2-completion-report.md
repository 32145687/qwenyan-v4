## 1. 实现内容

P11.2 建立第一条最小可运行链路：

```text
UserWritingRequest → PlanningContext → Planner Agent → AgentRuntime → LLMGateway(Mock)
    → ChapterPlan → Checkpoint(PLANNING) → COMPLETED / FAILED
```

### 1.1 Writing Context Assembly（PlanningContext + PlanningContextAssembly）

- [`PlanningContext`](file:///workspace/application/src/main/kotlin/com/qianyan/application/usecase/writing/planning/PlanningContext.kt)：`UserWritingRequest` + `novelId` + `variantId?` + `scope`（按 variantId 推导 ORIGINAL|VARIANT）+ Novel 背景（title/genre/synopsis）+ Variant（name/directive）+ 作用域可见 Memory / Vocabulary 的最小投影（`CharacterLite` / `VocabularyLite`）。
- **复用现有模型**：Novel / NovelVariant / MemoryEntry / Vocabulary / VocabularyEntry / UserWritingRequest 全部复用，**不新增第二套 Context 模型**。
- [`PlanningContextAssembly`](file:///workspace/application/src/main/kotlin/com/qianyan/application/usecase/writing/planning/PlanningContextAssembly.kt)：定位 Novel（缺 baseNovelId → InvalidOperation；不存在 → EntityNotFound）；Variant 可选并校验属于该 Novel（否则 VariantMismatch）；Memory/Vocabulary 按 Variant 作用域读取（不读其它 Variant）；仅投影 Planner 需要的字段，不把整个小说世界塞给 LLM。
- **Known Issue**：Character 无持久化仓储（`CharacterRepository` 不存在于当前 storage），故 `characters` 投影暂为空列表，已在代码注释与报告 Known Issues 中如实标注（后续 P11.3 持久化后接入）。

### 1.2 Planner Agent（PlannerAgent + ChapterPlanParser）

- [`PlannerAgent`](file:///workspace/application/src/main/kotlin/com/qianyan/application/usecase/writing/planning/PlannerAgent.kt)：只依赖 `:provider:api` 的 `LLMGateway` 抽象，经 P10 `AgentRuntime` 执行；**不直连 DeepSeek/MiMo/HTTP/API Key/Storage**；无业务 Tool（allowedTools 空）。默认 `ModelProfile.MOCK`，模型选择经 `LLMGateway`/`ModelProfile` seam 由装配方注入。
- [`ChapterPlanParser`](file:///workspace/application/src/main/kotlin/com/qianyan/application/usecase/writing/planning/ChapterPlanParser.kt)：解析 Planner 输出为**已有** `ChapterPlan`（[StoryModels.kt](file:///workspace/core/model/src/main/kotlin/com/qianyan/model/story/StoryModels.kt)），复用领域模型，**禁止重新创建**。
  - 结构 ID（novelId / arcId / actId / variantId / scope / chapterPlanId）由 `ChapterPlanStructure`（上下文）承载，**不让 LLM 生产领域 ID**；
  - 创作字段（chapterGoal 必填 / mainConflict / characterGoals / expectedEvents / emotionalDirection / endingHook / constraints / forbiddenEvents）来自 LLM；
  - 空输出 / 非 JSON / 缺 chapterGoal / 类型错误 → `PlanningException.InvalidOutput` → `ApplicationError.InvalidPlanningOutput`（**类型化错误，不经 String.contains**）。

### 1.3 ChapterPlan ↔ Checkpoint（PlanningSnapshot）

- [`PlanningSnapshot`](file:///workspace/application/src/main/kotlin/com/qianyan/application/usecase/writing/planning/PlanningSnapshot.kt)：`ChapterPlan` ↔ Checkpoint `snapshot`（JsonObject，带 `type=PLANNING` 标签）编解码；解码失败返回 null，不抛。
- **复用 P8.1/P8.2 的 `Checkpoint`**，不新增 Planning 表、无数据库 migration。

### 1.4 Planning 执行（PlanningExecutionUseCase）

- [`PlanningExecutionUseCase`](file:///workspace/application/src/main/kotlin/com/qianyan/application/usecase/writing/planning/PlanningExecutionUseCase.kt)：
  - 校验 Task.type == PLANNING（否则 InvalidOperation）；不存在 → TaskNotFound；
  - `PENDING → start → context assembly → planner.plan → saveCheckpoint(PLANNING) → complete → COMPLETED`；
  - 失败 → `fail`（记录类型化原因）→ 抛类型化错误 → FAILED；
  - `chapterPlanFrom(checkpoint)` 只读恢复 ChapterPlan（不重新执行，P8.2 语义）。

### 1.5 TaskRunner 最小放开

- [`TaskRunner`](file:///workspace/application/src/main/kotlin/com/qianyan/application/usecase/task/TaskRunner.kt)：新增 `executePlanning(taskId, request)` 专用入口，转发 `PlanningExecutionUseCase`；字节源 `execute` 仍仅 IMPORT；WRITING / KNOWLEDGE_UPDATE 仍抛 `UnsupportedTaskType`。**未改造成 Workflow Engine / Orchestrator，未实现 Agent loop**。

### 1.6 类型化错误

- [`ApplicationError.InvalidPlanningOutput` / `PlanningFailed`](file:///workspace/application/src/main/kotlin/com/qianyan/application/error/ApplicationError.kt#L101-L108) + [`PlanningException`](file:///workspace/application/src/main/kotlin/com/qianyan/application/usecase/writing/planning/PlanningException.kt) + [`ErrorMapper`](file:///workspace/application/src/main/kotlin/com/qianyan/application/error/ErrorMapper.kt) 接线，类型安全，绝不靠 String message 判断类型。

### 1.7 P10 AgentRuntime 最小修复

- [`AgentStep.kt`](file:///workspace/agent/runtime/src/main/kotlin/com/qianyan/agent/runtime/AgentStep.kt#L46-L53)：`AgentResponseParser` 对 `tool`/`answer` 值非 `JsonPrimitive` 时不再抛 `IllegalArgumentException`，而是安全回退 `AgentStep.Final`。**修复依据**：实际编译/测试证明该缺口存在（LLM 输出 `answer` 为对象/数组等非原始值时解析崩溃）。仅做最小修复，不改 P10 Agent loop 核心行为。
