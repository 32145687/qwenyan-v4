新增 Schema v2（SQLDelight，沿用既有 TEXT ID / INTEGER epoch 毫秒约定，未引入新技术）：

- `Task` 表：
  - `task_id TEXT PRIMARY KEY`
  - `type TEXT`（TaskType 枚举名）、`status TEXT`（TaskStatus 枚举名）——状态与领域枚举一一对应，禁止字符串随意模拟

  - `task_id TEXT`，`UNIQUE (task_id, revision)`，`FOREIGN KEY (task_id) REFERENCES Task(task_id)`
  - `revision INTEGER CHECK (BETWEEN 1 AND 3)`
  - `stage TEXT`（恢复点阶段标识）
  - `snapshot TEXT`（JSON `JsonObject` 或 NULL，沿用 `QianyanJson` kotlinx.serialization，未引入新 JSON 库）

迁移文件：`storage/src/main/sqldelight/com/qianyan/storage/db/1.sqm`（v1 → v2），仅新增 Task / Checkpoint，不删除/修改任何既有业务表。

## 3. Repository

- `TaskRepository`（storage 仓储契约，领域语义，不暴露 SQLDelight 生成类型）：
  `create` / `findById` / `update` / `delete` / `saveCheckpoint` / `findCheckpoints` / `findLatestCheckpoint`，命名遵循既有 Repository 风格。
- `SqliteTaskRepository`（SQLDelight 实现）：
  - `create`：Task 落库，若 `task.checkpoint` 非空则同事务落 Checkpoint；
  - `findById`：附带最近 Checkpoint 的派生视图（`Task.checkpoint` 由 Checkpoint 表最新 revision 填充，Task 表不冗余存储）；
  - `saveCheckpoint`：校验 revision ∈ [1,3]，同事务同步 `Task.revision_count` / `updated_at`，防止两表不一致；
  - `delete`：单事务删除 Checkpoint + Task，不留孤儿；
  - `findCheckpoints`：按 revision 升序；`findLatestCheckpoint`：revision 最大者。
- `StorageMappers`：`domainTask ↔ DbTask`、`domainCheckpoint ↔ DbCheckpoint`，双向映射（JSON 序列化 / 枚举名 / Instant ↔ epoch 毫秒）。`core:model` 不感知 SQLDelight / SQLite / SQL。
- 新增异常：`TaskNotFoundException`（阻止孤儿 Checkpoint）、`RevisionLimitExceededException`（revision 上限）。

## 4. Transaction Boundary

所有写路径均为单事务原子操作，不留半成品数据：

- `create`（Task + 可选 Checkpoint）单事务；Checkpoint 违反约束 → 整体回滚，Task 也不存在。
- `saveCheckpoint`：先校验 revision / 目标 Task 存在（读在事务外，防孤儿），再单事务执行
  Checkpoint INSERT + Task 同步更新；任一失败整体回滚（测试验证 Task 行保持原状）。
- `delete`：Checkpoint + Task 单事务。
- `update`：单事务。
- `DatabaseInitializer`：建表/迁移在单事务内执行并同步 `PRAGMA user_version`，任一步失败整体回滚。

未触碰 P6 已知的 VocabularyCandidate 非单事务问题（P6 legacy issue，明确不属于本任务）。
