## 2. 状态列口径

| 列 | 含义 |
|---|---|
| Implementation | 代码实现状态 |
| Automated Acceptance | 自动化测试/证据状态 |
| GUI Acceptance | 真实 GUI 交互验收状态 |
| Overall | 综合状态（任一规定验收未完成则不得为 DONE） |

状态词：`DONE` / `IN_PROGRESS` / `NOT_STARTED` / `BLOCKED` / `PENDING_VERIFICATION` / `DEFERRED`。

Phase 4 审计增量另使用两个验收子状态：

- `NOT_IMPLEMENTED`：能力/入口不存在，不能以占位或模型定义代替实现。
- `NOT_ACCEPTED`：代码可能存在，但规定的验收证据未成立。
- `BLOCKED_BY_PHASE_4`：阶段未启动/未通过，原因是对 Phase 4 的硬依赖尚未满足。

1. **GUI 验收未完成**：G1–G8 均为 `PENDING_VERIFICATION`，不能标记 DONE。

5. **无 P0-3B Schema/Migration**：历史报告与当前代码均无新增 Schema/Migration。
6. **Phase 4 / Phase 5 已按 v3.1 Gate 收口，Phase 6 第一单元完成**：Phase 4 §13 与 Phase 5 §14 Gate 均有自动化证据；Phase 6 字段生产读取已实现；MVP Gate 仍缺 LongContinuation 映射与 CharacterConsistency 行为契约。P0-3B GUI G1–G8 仍是独立 `PENDING_VERIFICATION`。
